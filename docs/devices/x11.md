# Attack Shark X11

This page is the model-level entry point for the Attack Shark X11 protocol dialect. Packet definitions live in [`../protocols/`](../protocols/README.md); transport framing lives in [`../transports/`](../transports/README.md).

## Identity and support

| Variant | PID | Driver mode | Transport | Status |
|:--------|:----|:------------|:----------|:-------|
| X11 wired | `0xfa55` | `wired` | USB HID | Supported |
| X11 2.4 GHz adapter evidence | `0xfa60` | `adapter` | USB HID | Historical/model-qualified |
| X11 Bluetooth | Unknown | — | BLE | Not tested |

PID `0xfa60` identifies the shared 2.4 GHz receiver, not a unique X11 model.
The receiver can carry X3/M600-family traffic; X11 packet samples in this page
must not be generalized to every device paired through an FA60 receiver.

The current maintainer has X3-family hardware, not an X11. X11 behavior is therefore preserved from the production implementation, existing captures, and prior reverse-engineering rather than newly generalized from X3 results. Changes to X11 behavior require independent X11 evidence.

## Protocol coverage

| Feature | Report / path | Notes |
|:--------|:--------------|:------|
| DPI | [`0x04`](../protocols/04-dpi.md) | Exactly six stages; encoded through the X11 lookup table; maximum 22,000 DPI |
| Preferences | [`0x05`](../protocols/05-preferences.md) | X11 state byte and 8-bit checksum dialect |
| Polling rate | [`0x06`](../protocols/06-polling-rate.md) | 125, 250, 500, and 1000 Hz |
| Button mapping | [`0x08`](../protocols/08-button-mapping.md) | X11 slot order and checksum dialect |
| Custom macros | [`0x09`](../protocols/09-custom-macros.md) | X11 page-2 header uses `09 0c` |
| Reset/profile load | [`0x0c`](../protocols/0c-profile-reset.md) | Six-byte wired or ten-byte adapter payload |
| Battery | [X11 adapter interrupt report](../protocols/battery.md) | Available from endpoint `0x83` in adapter mode |

## Evidence

X11 descriptors, packet captures, and sample payloads are catalogued under [`../evidence/x11/`](../evidence/x11/README.md). These artifacts remain model-qualified; they must not be used as proof of X3 behavior without separate evidence.
