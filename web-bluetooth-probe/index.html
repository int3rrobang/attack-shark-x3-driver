Device

"Use permitted device" tries the optional getDevices() API. "Choose device" opens the browser chooser; the device may need to advertise on the selected RF slot, but you do not need to unpair from the OS. Tested Chromium builds lacked usable permission reuse, so expect to use the chooser each session.

Hard-blocks: Report 0x06 is blocked over BLE. Report 0x05 with byte 3 = 0x00 is blocked (known BLE firmware crash risk — LightMode.Off). No FFC0/FFC1/FFC2 access is exposed.
ACK correlation: correlation is by report ID only (no transaction ID). Same-RID packets may mis-correlate stale ACKs. FEE1 reads before/after are observational snapshots only, not proof.
